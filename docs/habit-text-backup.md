# 習慣の文章入力・追加アイコン・自動バックアップ

2026-11-26。今回の作業はローカル実装中。現行公開版20261126-154700のメモ改修とは別。Googleへの反映・追加認可・実コピー・自動ONはまだ行っていない。

## 変更

- 習慣の入力方式に `text`（文章、改行可）を追加。単位は不要。日付ごとの値をネイティブtextareaで記録し、履歴でも改行を表示する。
- 既存の50アイコンはそのまま残し、画像アイコン20種類を追加。保存値は `habit-image:<key>` で、画像のデザインを変えても項目idや文章を移行しない。
- 追加20種類：自転車・水泳・掃除・洗濯・歯みがき・入浴・休息・水分補給・牛乳・お茶・卵・野菜・果物・ペット・植物・パソコン・書く・家計・映画・パズル。
- 設定に自動バックアップを追加。Google保存済みのスプレッドシートを全体コピーする。既存ソースにバックアップ実装はなかった。旧仕様の「3時バックアップ」の記述だけで実装済みとは扱わない。

画像はimagegen内蔵ツールでA/B/Cの3案を生成し、選定待ち。現時点の `icons/habit-icons.png` は試作用のA案。候補と生成プロンプトは作業成果物 `habit-text-backup/habit-icons-{a,b,c}.png` / `icon-prompts.json` に保存。Aは塗り、Bは太い輪郭、Cは淡色。画像の選定前に正式公開しない。

## 文章の保存と既存データ保護

日別キャッシュを全体置換する送信は行わず、編集した日・項目の `set` / `del` だけを既存outboxへ入れる。既存の数値0・チェック・時刻・未知フィールドは維持。既存項目の編集では未知メタデータも引き継ぐ。無編集の開閉ではCRLF・先頭空行・末尾空白を保存し直さない。

入力直後にキャッシュと復旧情報を永続化し、通信だけ700msまとめる。入力中のDOMを再描画せず、Enterは改行として扱う。復旧情報が残る日、未送信や取得開始後の編集がある日は、通常取得と履歴取得の古い結果でキャッシュを上書きしない。ローカル保存が失敗した場合は見えている文章を保持し、日付・タブ移動を止める。アプリ本体の更新も未送信・復旧待ちでは停止する。

復旧マーカーは意図した値を保持し、日別キャッシュと完全一致しなければ再送しない。これはマーカー成功→本文書込み失敗→マーカー巻戻し失敗の二重エラーで、古いキャッシュをサーバーへ送らないため。別日・同日同項目を開き直した後の遅延イベントも検証対象。

モジュール：`js/habit/text.js`（入力・復旧）、`js/habit/icons.js`（画像カタログ）、`js/backup/client.js`（状態取得）。メモ本文・Healthの読み取りルール・既存の日別API形式は変更しない。

## バックアップの範囲と管理

有効化時に初回コピーを検証してから、日本時間3時台の日次トリガーを登録する。手帳を閉じていてもGoogle側で実行する。元のスプレッドシートは読取りと `copy()` のみ。過去のコピーは自動削除しない。

タスク、メモ、習慣、食事、目標、添付画像を含む全シートを対象とし、将来増えるシートも全体コピーに含む。端末だけの設定・未送信/編集中の内容・Healthキー・外部Googleカレンダーは対象外。取り込み済みのHealth値は習慣の記録として対象。復元で原本を上書きする機能は設けない。まず別コピーの内容と日付を確認する。

匿名GET `backup_status` が返すのは enabled / lastSuccessAt / lastErrorCode / hasBackups の4項目のみ。コピーID、URL、氏名・メール、記録本文は返さない。設定変更・コピー一覧・手動コピーは、Google本人のactive/effective email一致を確認する管理画面とRPCだけで行う。自動workerはUID/owner/handlerを照合する。OFFは記録済みの専用トリガーだけを消し、他のジョブには触らない。

コピーや検証・台帳保存・トリガー登録の失敗は成功として表示しない。作成済みのコピーを失敗処理で削除しない。コピーの共有設定は変更せず、Googleのコピー動作に従うため、本人だけが見られると未確認で断言しない。管理画面で初回の共有範囲確認を案内する。

## 公開前のGoogle追加認可

新たな権限は `script.scriptapp`（専用トリガー管理）。既存spreadsheets等を維持し、Drive全体権限は追加しない。利用者の新しいキー設定は不要。

1. 実装と画像選定を完了し、本人の公開承認を得る。
2. 新source・manifestをApps Scriptへ保存する。現行deploymentはこの段階で切り替えない。
3. 管理者本人がApps Script editorで `Backup.gs` の `getBackupStatus` を選び、Googleの追加認可を確認する。末尾underscoreの `authorizeBackupSetup_` はeditorの選択一覧に表示されないことを実UIで確認したため、状態だけを読む関数を入口にする。新規権限の許可はその場で本人へ確認する。状態取得は本文の取得、コピーやトリガーの作成・削除を行わない。
4. 再実行が成功してから同じdeploymentを新versionへ切り替える。認可前に切り替えると既存APIも止まる可能性があるため順序を守る。
5. 管理ページの本人認識と状態表示を確認する。Google Drive保存先の選択が確定した後、管理画面からONにし、初回コピーと共有範囲、最終成功を確認する。
6. GAS反映を待って画面側を公開し、公開ファイルのSHAを確認する。

実Googleの認可画面・本人識別・コピーの保存先/共有・時間トリガー実行は、現時点では未確認。合成試験の成功と混同しない。

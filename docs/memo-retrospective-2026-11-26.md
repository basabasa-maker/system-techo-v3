## 改善して良かったこと

1. **本文と装飾を同じ面へまとめた。** 取り消し線は実文字のtext-decoration、罫線は本文側の32px背景タイル。別textarea・ミラー・偽カーソル・スクロール同期を廃止し、罫線ON/OFFも本文保存から分離できた。
2. **保存形式を変えずにライブラリを導入した。** CodeMirrorを選び、既存プレーンテキスト・チェック文字・添付トークンを保持した。無編集の開閉やタイトルだけの編集では原文のCRLF・空白・末尾改行をそのまま返す。元データの一括変換は行わない。
3. **入力・本文変換・保存保護を分けた。** `editor.js` / `document.js` / `repository.js` に責務を分離。曖昧な添付形式の入力やローカル保存失敗では、入力画面を残して黙って捨てない。
4. **通信失敗とキュー永続化失敗を別に確認した。** localStorage本文保存後にIndexedDB enqueueだけが失敗すると、再起動で保護が消える。ID・操作種別・tokenだけの復旧マーカーを追加し、古いGETによる本文の巻戻し・削除済みメモの復活を防いだ。
5. **実際の保存まで確認した。** 新規、既存短文、長文、チェック追加の4経路で実キーボードを使い、画面・状態・保存本文を比較した。短文の元本文全体と長文のチェックを保持できた。
6. **担当と編集範囲を明確にした。** 実装、保存保護の読取レビュー、ブラウザーQA、native検証を分担した。同じソースを共有し、最終のsource SHAを揃えて結果を照合した。並行作業中の別ソースの結果を混ぜない。
7. **オフライン配信まで含めた。** ライブラリ本体は固定版を同梱し、ライセンス・再生成情報も保持した。新しいruntimeをversion.jsonへ含め、公開後の55ファイルが実際に一致することを確認した。

## 次に同種の変更をするとき

1. 現行版と今回の完了状態を読む。旧候補・失敗variant・旧自前カーソルの説明は、歴史の記録として区別する。
2. 本文と保存形式を先に確認し、無編集開閉・チェック・添付・未知メタデータ・末尾空白/改行を保持するケースを用意する。
3. 修正前に、画面のどの層が動くかを測る。window、visualViewport、アプリ枠、本文scroller、カーソルを別々に記録する。
4. 入力系はnative tap・キーボード・日本語変換の確定・保存まで実行する。短tap、長押し、指移動、複数指、すでに入力中、Undoも確認する。
5. 単独の回避実験が成功したら、実際のモジュールへ組み込み、実験用のprototype変更や応答差替えを外して同条件で再検証する。
6. 本文保持・遅延保存・オフライン・enqueue失敗後の再読込・遅延添付・削除復活を合成APIで確認する。本番データを試験に使わない。
7. 最終source SHA、測定、保存本文、公開版番号をまとめる。承認後に配信版を更新し、GitHubの成功表示と公開ファイルの実体を照合する。

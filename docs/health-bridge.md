## 操作

1. 習慣の入力画面で「ヘルスケア連携」を開く。初期状態はOFF。
2. この手帳の連携キーをコピーし、[追加用ZIP](../shortcuts/health-bridge/system-techo-health.zip)をダウンロードする。「ファイル」→「ダウンロード」でZIPを展開し、中の署名済み `.shortcut` を開く。「ショートカットを設定」の質問へキーを貼り付けて追加する。
3. 手帳とショートカットの名前を合わせ、手帳で連携をONにして保存する。
4. 対象日を表示し、右上の「更新」を押す。ショートカットが前面へ出て、その日だけを読み取る。読み取り許可は本人がiPhoneで行う。
5. Safariが開いた場合は元のホーム画面の手帳へ戻る。自動で同じPWAへ戻ることは未確認なので保証しない。
6. 初めて届く項目は、同じ日のヘルスケア表示と数値・単位を照合してから取り込む。確認済みの項目は次回から自動で反映する。初回確認の「取り込まない」では保存しない。

[詳細なiPhone手順と検証限界](../shortcuts/health-bridge/README.md)。キーを入れた個人用ショートカットは再配布せず、公開するのはキー未設定のテンプレートだけとする。

## データの意味と保持

| 項目 | 対象日の取り方 | 単位 |
|---|---|---|
| 体重 | その日内の最新測定 | kg |
| 体脂肪率 | その日内の最新測定 | %表示値 |
| 消費カロリー | その日のアクティブエネルギー集計 | kcal |
| 歩数 | その日の集計 | count |

- 欠測はキーを省略し、0で埋めず、前日や前回の値を繰り越さない。既存値も消さない。サンプルの実値0は保持する。
- 書き込みは、明示的に更新を開始した対象日の取得できた項目だけを `habit_day_upsert` のPATCHで保存。全日更新や過去日の一括補正は追加しない。
- ショートカットから習慣シートへ直接書かない。GASの最大10分のScriptCacheへ受信し、PWAが日付・リクエスト・連携キー・手入力・未送信を照合してから保存する。Cacheの早期消失は待機として扱い、欠測を権威的な空記録に変換しない。
- 読み取り待ち中の手入力は、元の値へ戻した場合も保護する。日付やタブを変えた画面には遅い結果を書かない。取り込みを確定して保存が始まった後は、中止と設定変更を無効にして保存中と表示する。
- 機能未連携なら既存の更新動作を維持。起動・通常タブ表示・日付変更で新しいHealth読み取りを始めない。中断した明示リクエストがある場合の再開だけは行う。初回のキーは連携OFFの状態でも端末へ記憶し、ショートカット追加中にPWAが再生成されても同じキーを使える。既存キーの未保存の編集は反映しない。
- 既存シート構造、localStorage schema4、IndexedDB `sth_v3` v1、添付キャッシュは変更しない。

## 構成と通信

- `js/health/model.js`：単位/値/対象日/期限の検証と、手入力を守る部分更新選択。
- `js/health/bridge.js`：端末設定、1回限りの待機情報、起動URL、認証付き受信と消費。
- `js/health/ui.js`：初期設定、初回の値確認、Safariへ戻った場合の案内。
- `js/habit.js`：手動更新から起動、明示リクエストの再開、既存キューへの保存。
- `gas/Code.gs`：`health_bridge_upload` / `health_bridge_read` / `health_bridge_ack` のPOSTだけを追加。SheetやPropertiesを使わず一時Cacheへ保存する。
- 設定は `sth_v3_health_settings`、待機は `sth_v3_health_pending`、最終取り込みのメタ情報は `sth_v3_health_last_sync`。既存キーには触れない。
- 連携キーはランダム32bytesのbase64url。端末と個人用ショートカットで共有し、GAS Cacheにはハッシュだけを保持する。
- 起動URLには `request_id / date / issued_at` だけを渡す。健康値や連携キーはURLへ入れずHTTP本文に限る。ショートカットの送信先と戻り先は生成時に固定する。
- 別キー・別日・別開始時刻・期限切れの結果を拒否し、最初の結果を再送で上書きしない。消費後は値を除去して短時間の消費済みマーカーだけを残す。

## request_id「値未指定」の修正（2026-11-25、公開前）

本人の実行で、4項目の許可後に送信辞書のrequest_idを設定するアクションで停止。旧テンプレートのWFDictionaryValueへ単独WFTextTokenAttachmentを入れた形式が原因。健康情報も通信もないmacOS合成Shortcutで同じエラーを再現し、単一変数のWFTextTokenStringへ直すと正常JSONを出力した。文字列・数値時刻・小数・0・入れ子・空辞書を照合済み。4項目の取得条件・日付・単位・欠測の扱い・送信先・戻り先・GAS・手帳の保存処理は変更しない。旧形式を正しいとした過去の構造チェックは不十分だったため、3件のPython試験とこの実行結果へ置き換える。

設定画面の配布リンクはZIPへ変更。ZIPはキー未設定の署名済みShortcut一つだけを含む。iPhoneで単体ファイルへ.htmlが付く誤保存を避ける。旧版を削除せず修正版を別名で追加し、手帳の呼出名をその実名へ合わせる方法でも差し替え可能。既存キーを再使用する。端末へ追加済みのShortcutは公開しても自動更新されない。

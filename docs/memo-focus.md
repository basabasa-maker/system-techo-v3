# メモの初回入力で画面が動く問題（2026-11-26、公開承認済み）

公開版 `20261126-134727` のメモを開いて本文をタップすると、画面が下の方へ移動して先頭から書きにくいと本人から報告があった。保存形式・罫線・取り消し線は維持し、初回フォーカスと位置計算を修正し、検証で見つかったチェック追加直後のカーソル位置も修正した。

## 観測と修正

- iPhone 17 / iOS 27 Simulator Safariの実際のタップと日本語ソフトウェアキーボードで、旧版はwindow/vvの位置が0→70px、メモの本文上端が258→118pxへ動いた。本文内のscrollTopは0のままで、本人の「本文末尾まで飛ぶ」現象そのものを同じ形で再現したという意味ではない。
- 上端に `getBoundingClientRect().top` を使うと、OSが動かした70pxをfixed配置でもう一度反映する。mainはtop:0のfixed app-shell直下なので、同じレイアウト座標の `offsetTop` を使う。
- CodeMirrorのSafari 26以降のfocus fallbackはnativeへ明示の `preventScroll:true` を渡さず、同期のスクロール復元を使う。これでは後から起きるキーボード表示の画面移動を止められなかった。
- 最初の短いタップだけ標準のフォーカスを抑止し、実際の本文から `posAtCoords` でカーソル位置を求める。先にpublic selection dispatchで実カーソルを確定し、その後にnative `focus({preventScroll:true})` を行い、空のpublic dispatchで同期する。native focusを先に行う順序は実キーボード検証で失敗したため使わない。
- この順序をiPhone/iPadの本文初回タップ・チェックツールバー・公開focus APIに共通で使う。すでに入力中、長押し、8px超の指移動、複数指、キャンセル、選択範囲、スクロール中、チェック等の操作は標準動作を維持する。日本語変換中もタップを取り上げない。
- 空行や行頭でチェックを追加した際、カーソルがチェック記号の前に残ると日本語IMEの文字が保存されない境界を確認した。範囲選択のないカーソルが新しいprefix挿入位置と一致する場合だけ、同じ編集transactionでprefix後ろの位置2へ移す。既存prefixの解除、範囲選択、本文途中のカーソルは従来のmappingを維持する。
- ミラー、偽カーソル、透明化、画面全体のtranslate、window.scrollToによる引き戻しは追加しない。既存本文・添付・チェック・メタデータ、保存先、保存の形式やタイミング、他タブは変更しない。

## 最終ソースの検証

検証はlocalhost専用の合成メモと合成APIのみ。実記録APIは呼ばず、普段のブラウザや実iPhoneのデータにも触れない。

### 実キーボード

Xcodeの公式XCUITestでnative coordinate tap、日本語キーボードの表示assertion、「あ」キーと改行キーによる変換確定を行った。Simulator.appのGUIがなくても、既存SDK・XCTest・testmanagerdで実行できる。native試験のfixtureは外部通信をCSPで遮断する。

最終ソースをそのまま配信し、prototypeのフォーカス上書きや応答差替えの実験variantは無効化して確認した。

| 合成メモ | 実操作と結果 |
|---|---|
| 空 | 本文タップ→日本語「あ」を入力して確定→保存本文が「あ」 |
| 短文 | 先頭タップ→日本語「あ」を入力して確定→保存本文は「あ」＋既存本文。元の本文全体をそのまま保持 |
| 長文 | 先頭タップ→日本語キーボード表示、本文・チェック変更なし、保存POST増加なし |
| 空からチェック追加 | チェック追加→日本語「あ」を確定→画面と保存本文が「☐ あ」で一致。変換中ではないことも確認 |

最終4ケースの全requestAnimationFrame記録（空701・短文738・長文454・チェック追加726）でwindowYとvv.offsetTop、本文scrollTopは0のまま、本文上端258px・メモ上端110pxを維持した。CSSで動きを打ち消す検証用処理は使っていない。

最終動画は全1280フレームを間引かずdecodeして別に測定。メモのオレンジ境界を検出できた1098フレームすべてで画面上のY座標516px、境界のない182フレームは未分類として記録し、勝手に成功判定していない。

この確認はSimulator Safariである。ホーム画面PWA・物理iPhoneでの同じ入力は未確認として区別する。

### ブラウザーと保存保持

`tests/memo-focus.cjs` は27ケースをChrome/WebKitそれぞれで確認。OSキーボードの移動自体はheadlessでは再現できなかったため、実native証拠と分ける。初回タップ抑止、実native focus引数、focus時点の選択位置、追記保存/Undo、IME/長押し/スクロール等の例外、観測した座標値の再生を確認する。

既存メモ20ケースの回帰、本文・復旧・契約のNode32件も成功。既存composition試験はローカル保存完了とAPI試行の到着を区別する待機を追加した。失敗時の1件は変換中の本文ではなく、直前の確定済み本文だったことをpayloadで確認し、変換中の保存禁止assertionは維持した。

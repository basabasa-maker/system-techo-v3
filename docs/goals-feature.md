# 目標・ビジョンボード

2026-11-24。共有の現役ツリーへ実装し、公開前の検証を完了。本番は未反映。公開候補版 `20261124-233508`。

## 使い方

- 「目的一覧」「目標一覧」「ビジョンボード」を独立して切り替える。切り替え行はヘッダー直下に固定し、本文だけスクロールする。
- 目的は価値観、目標は達成内容、手段は具体的行動。目的1件→目標複数件→手段複数件。
- 追加は右下の「＋」へ集約。「目的を追加」「目標を追加」で入力画面を開き、ボードでは「写真を追加」も選べる。
- 手段は目標カードから追加・編集。一覧にも一部と件数を表示する。
- ボードとカードは同じ添付を参照。1目標に複数画像を結び、表紙を指定できる。
- 写真は長押ししてそのまま移動する。短くタップすると説明・目標編集、傾き・大きさ変更、関連目標、写真削除のメニューが開く。配置モードの切り替えは不要。削除は確認を挟み、元画像と目標を残す。
- 長押し前の移動はボードのパン。移動は指を離したときだけ保存し、キャンセルやピンチでは元の位置へ戻す。長押し後にメニューを誤って開かない。
- タブ列は横スクロール、長押しで揺れる表示と並べ替え。順序は端末に保存。Alt＋左右キーでも操作可能。

## 分担

`js/goals.js` は画面制御、`goals/ui.js` は入力画面、`goals/board.js` は座標・パン・ピンチ・写真移動、`goals/model.js` は検証と取得結果の統合、`goals/repository.js` はキャッシュと永続キュー、`tab-navigation.js` はタブ順序を担当する。画像は既存 `memo/attachments.js` を再利用する。

## データ保持

GASに新3シート `goal_nodes` / `goal_boards` / `goal_board_items` を追加する。行は `id / json / updated_at`。既存6シート・既存列は変更しない。

GET `goals` → `{nodes, boards, items}`。POSTは `goal_node_upsert {node}`、`goal_board_upsert {board}`、`goal_item_upsert {item}`。新書込みをScriptLockで保護し、部分更新と不明フィールド保持を行う。

新端末キャッシュは `sth_v3_goals_cache`、タブ順は `sth_v3_tab_order`。既存schema4・IndexedDB名と版は維持。新goal操作だけ元のキューID順に送り、目的→目標→画像→表紙の依存を守る。旧機能の統合規則は維持する。

未送信や取得後の編集を古い応答で戻さない。取得失敗・未対応API・破損キャッシュを空データへ置換しない。画像アップロード後は最新データへ参照のみ追加し、その間の編集や画面遷移を守る。写真増加時はボードを拡張し、初期位置を範囲内へ保つ。

削除は論理削除。目標から画像へ連鎖削除せず、ボードから外しても元の添付ファイルを削除しない。

## 公開と範囲

GASの新APIと画面の両方の反映が必要。先にGASを反映・検証し、その後HTML/SW等の版を更新して公開する。旧GASのままでは新記録が送信待ちになるため、フロントだけ先に公開しない。公開承認前にpush・clasp・デプロイを行わず、既存記録の初期化や移行スクリプトも実行しない。

新しい写真の追加には通信が必要。取得済み写真の閲覧と説明・位置の記録はオフラインでも使える。背景はコルクのみ。複数端末で同じ項目を同時編集する場合は最終書込みが優先される。iPhone実機の写真選択・キーボード・ホーム画面PWAとService Worker配信は今回の確認対象外。

2026-11-24の操作変更では、メニュー未実装の失敗を確認してから長押し/タップを分離した。影響するブラウザ10項目を再実行し成功（残る非影響項目は前回確認済み）。449ms/450msの境界やタイマー破棄は偽時計の実コードDOM試験でも確認した。案内には案の番号を使わず、目的一覧・写真付きの目標一覧・ビジョンボードの画面名を使う。
